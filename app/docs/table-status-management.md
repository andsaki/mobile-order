# テーブルの状態管理ドキュメント

このドキュメントでは、モバイルオーダーアプリケーションにおけるテーブルの状態管理について説明します。テーブルの状態がどのように更新され、どの部分で管理されているかを以下にまとめます。

## テーブルの状態とは

テーブルの状態は、レストランやカフェなどの店舗内での各テーブルの利用状況を示します。このアプリケーションでは、以下の状態が定義されています：

- **available (利用可能)**: テーブルが空いており、すぐに利用できる状態。
- **occupied (使用中)**: テーブルが現在顧客によって使用されている状態。
- **needs_cleaning (清掃が必要)**: テーブルが使用済みで、清掃が必要な状態。

これらの状態は、Supabase データベースの `tables` テーブルに保存されており、`table_id` で識別される各テーブルのレコードに `status` フィールドとして記録されています。

## テーブルの状態更新のタイミング

テーブルの状態は、以下のタイミングで自動的に更新されます：

1. **注文が行われた時**:

   - 注文が確定すると、テーブルの状態が `occupied` (使用中) に設定されます。
   - この処理は、`app/features/order/utils/order.server.ts` 内の `placeOrder` 関数で行われています。以下のコードが該当します：
     ```typescript
     if (tableId) {
       const { data: tableData, error: tableError } = await supabase
         .from("tables")
         .upsert([
           {
             table_id: String(tableId),
             status: "occupied",
             last_updated: new Date().toISOString(),
           },
         ]);
       // エラーハンドリングコード
     }
     ```

2. **支払いが完了した時**:
   - 支払いが完了し、注文履歴が削除されると、テーブルの状態が `needs_cleaning` (清掃が必要) に設定されます。
   - この処理は、`app/routes/api_.delete-orders.tsx` 内のアクション関数で行われています。以下のコードが該当します：
     ```typescript
     const { error: tableError } = await supabase
       .from("tables")
       .update({
         status: "needs_cleaning",
         last_updated: new Date().toISOString(),
       })
       .eq("table_id", tableId);
     // エラーハンドリングコード
     ```

## 手動での状態更新

管理者インターフェースを通じて、テーブルの状態を手動で更新することも可能です：

- 管理者ページ (`app/routes/admin._index.tsx`) では、各テーブルの現在の状態を確認し、ドロップダウンメニューから新しい状態を選択して更新できます。
- 更新は Supabase の `tables` テーブルに反映され、`last_updated` フィールドに更新日時が記録されます。

## 状態管理の流れ

1. 顧客が QR コードをスキャンしてテーブルに着席し、注文を行います。
2. 注文が確定すると、テーブルの状態が `occupied` に更新されます。
3. 顧客が食事を終え、支払いを完了すると、注文履歴が削除され、テーブルの状態が `needs_cleaning` に更新されます。
4. 必要に応じて、管理者が手動で状態を `available` や他の状態に変更することができます。

## まとめ

テーブルの状態管理は、顧客の体験と店舗運営の効率を向上させるために重要な機能です。このアプリケーションでは、注文と支払いのプロセスに連動して自動的に状態が更新されるだけでなく、管理者による手動更新もサポートしています。これにより、テーブルの利用状況をリアルタイムで正確に把握することが可能です。
